# 闹钟保持系统委托，联动发生在设置时刻

SleepCycle 不自建应用内闹钟（AlarmManager + BroadcastReceiver），继续通过 `ACTION_SET_ALARM` Intent 委托系统闹钟。代价是应用**无法感知响铃**——因此"闹钟 ↔ 睡眠记录"的联动发生在用户**设置闹钟的时刻**：首页推荐时间卡（起床锚点）设闹钟时，按睡眠日归属把起床时间写入对应记录；而不是响铃时记录真实起床时刻。

自建闹钟能获得真实响铃/起床时刻并支持应用内联动，但需要 Receiver、精确闹钟权限、勿扰与厂商适配，是一次大重构；对"计划=实际"的使用方式（见 ADR-0001）收益有限。

## Considered Options

- **自建应用内闹钟**：完整掌控闹钟生命周期，可自动记录真实起床时间；复杂度远超当前需求，若未来需要真实起床数据再单独立项。
- **延迟写入（闹钟时间先存内存/偏好，到期再落库）**：避免放宽日期校验，但多一份需持久化的状态，进程被杀即丢失。

## Consequences

- 只有起床锚点（首页推荐时间卡）参与写入联动；小睡提醒、晨间光照、数字日落闹钟保持纯提醒。
- 覆盖规则为"后来者覆盖"：用户主动操作即明确意图，应用不做保护性拦截。
